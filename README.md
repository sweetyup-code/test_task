# Тестовое задание — «Рыжий Кот»

## О проекте

Тестовое задание на разработку страницы «О компании» с адаптивной версткой, интерактивными элементами и обработкой формы обратной связи.

## Запуск проекта

Для корректной работы проекта требуется локальный PHP-сервер, так как обработка формы выполняется через PHP.

Для запуска использовался **Open Server (OSPanel)**:

1. Разместить папку проекта в директории, подключенной к OSPanel как корень сайта.
2. Запустить OSPanel.
3. Открыть проект через локальный домен в браузере.
4. Проверить работу формы обратной связи и интерактивных элементов.

> Открытие `index.html` напрямую через файловую систему (`file://`) не рекомендуется, поскольку обработчик формы использует PHP.

## Используемые технологии

* **HTML5** — семантическая разметка страницы.
* **CSS3** — стилизация, Flexbox, Grid, адаптивная верстка и медиазапросы.
* **JavaScript (ES6+)** — интерактивность, работа с модальными окнами, валидация формы и AJAX-запросы.
* **PHP** — обработка отправленных данных формы.
* **Fetch API** — асинхронная отправка данных без перезагрузки страницы.
* **JSON** — формат передачи данных между JavaScript и PHP.
* **SVG** — встроенные в HTML векторные иконки.
* **Regex** — проверка введенных пользователем данных.

Сторонние JavaScript-фреймворки и библиотеки не использовались.

## Реализованный функционал

* Адаптивная верстка страницы.

* Навигация с использованием семантической разметки.

* Асинхронная отправка формы через Fetch API.
* Передача данных в формате JSON.
* Обработка JSON-ответа от PHP.
* Обработка данных на стороне PHP.

## Самостоятельные технические решения

Помимо требований технического задания, были самостоятельно реализованы дополнительные элементы, направленные на улучшение структуры проекта, пользовательского опыта и демонстрацию работоспособности функционала.

### Локальное подключение шрифтов

Шрифты были вынесены в отдельную папку проекта и подключены локально через отдельный файл `fonts.css`.

Это позволяет:

* не зависеть от внешних сервисов при загрузке шрифтов;
* хранить все необходимые ресурсы непосредственно в проекте;
* отдельно управлять подключением и начертаниями шрифтов.

### Ссылка на документ о персональных данных

Для пункта согласия на обработку персональных данных реализован переход на отдельный PDF-документ.

При нажатии на соответствующую ссылку пользователь может открыть документ с условиями обработки персональных данных вместо использования обычной текстовой заглушки.

### Информационное окно для разделов в разработке

Для кнопок меню и авторизации, функциональность которых не была реализована в рамках тестового задания, добавлено отдельное информационное модальное окно.

Вместо того чтобы оставлять кнопки без реакции или использовать пустые заглушки, пользователь получает понятное сообщение о том, что соответствующий раздел находится в разработке.

Это позволяет сохранить ожидаемое поведение интерфейса и сделать взаимодействие с сайтом более понятным.

### Демонстрация передачи данных формы

Для демонстрации корректной передачи данных формы реализована их запись в `.txt`-файл.

После отправки данные передаются через `Fetch API` в PHP-обработчик, после чего сохраняются в текстовый файл.

Такой вариант был выбран вместо подключения базы данных, поскольку для демонстрации работы формы в рамках тестового задания полноценное подключение БД не требовалось.

При этом можно проверить полный цикл передачи данных:

`Форма → JavaScript → JSON → PHP → TXT-файл`

## Принятые технические решения

### CSS

Для построения интерфейса использовались:

* `Flexbox` — для выравнивания и построения линейных блоков;
* `CSS Grid` — для сеточных элементов;
* медиазапросы — для адаптивной верстки;
* относительные единицы измерения там, где это необходимо для адаптации;
* логическое разделение CSS-свойств по блокам и назначению.

### JavaScript

Для интерактивной части использовался чистый JavaScript без сторонних библиотек.

Для отправки формы используется асинхронная модель:

```javascript
async/await
try/catch
Promise
Fetch API
```

Данные формы преобразуются в JSON и передаются PHP-обработчику без перезагрузки страницы.

### SVG

Иконки встроены непосредственно в HTML в формате SVG. Это позволяет управлять их размерами и расположением через CSS и не создавать дополнительные запросы к отдельным файлам изображений для каждой иконки.

### Валидация

До отправки формы выполняется клиентская проверка введенных данных с использованием регулярных выражений.

Это позволяет сразу сообщить пользователю о некорректном вводе и не отправлять заведомо некорректные данные на сервер.

При это валидация данных так же происходит и на стороне сервера.
